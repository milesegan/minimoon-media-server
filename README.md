# MiniMoon Media Server

The LAN media server behind the MiniMoon and Matinee apps. It shares folders of music and
video with devices on the same network over the MiniMoon Media Protocol (MMP) v1, specified in
[docs/minimoon-media-protocol-v1.md](docs/minimoon-media-protocol-v1.md).

- **One index, one request.** Clients download the whole index of every shared folder, with a
  weak ETag and `304 Not Modified`, and keep a local copy.
- **Facts, not interpretation.** Tags are read with a copy of the apps' own tag reader, and
  video stream facts (codecs, HDR, Dolby Vision, tracks) with a native Rust reader.
- **Read-only.** Nothing is ever written into the shared folders.
- **No accounts.** Open to the local network by default, with an optional six-digit pairing
  code for new devices.

This replaces the Sync server's protocol (`/files`, `/file-by-path` on port 41324), which is
gone. The apps handle the move to MMP.

## CLI

```sh
cargo install minimoon-media-server
minimoon-media-server ~/Music ~/Movies
```

From a source checkout:

```sh
cargo run --release -- ~/Music ~/Movies
```

Folders given on the command line are added to the saved shared folders, so later runs need no
arguments. The server publishes everything under its shared folders. It prints a
summary that marks any shared folder it isn't serving yet: a folder is shared only once its first
index is complete. In a terminal, a progress bar shows indexing and background metadata updates.
The server then prints a line when a folder becomes shared or goes offline, a line once the first
scan has indexed everything, and a pairing code whenever a device asks to pair.

Options:

- `--data-dir <dir>`: where the settings, index and art cache live. The default is
  `com.plastaq.sync-server/media-server` in the platform's app-data folder (on macOS,
  `~/Library/Application Support`).
- `--port <port>`: the port to listen on, 41325 by default.
- `--bind <address>`: the address to listen on; every IPv4 interface by default.
- `--name <name>`: the display name devices see (saved). The host name by default.
- `--pairing` / `--open`: require a pairing code for new devices, or let any device on the
  network connect (saved).
- `--no-bonjour`: don't advertise `_mmserver._tcp` over Bonjour.
- `--reindex`: re-read every file's metadata in the background.
- `-v`, `--verbose`: log requests and scans.

Anything in a shared folder the server can't read is treated as not there, and the server
prints which paths failed. Symbolic links are never followed, wherever they point: to share a
drive or another folder, add it as a shared folder of its own.

## Desktop app

On macOS, download the DMG from [GitHub Releases](https://github.com/milesegan/minimoon-media-server/releases),
open it, and drag **MiniMoon Media Server** to Applications. The signed and notarized installer
contains both Apple silicon and Intel builds.

`gui/` is a small Tauri app that runs the server in-process and controls it: pause and resume,
shared folders (add, rename, remove, rescan, open in the file manager), reindexing, the display name, open or pairing
access, keep-awake, pairing codes as they arrive, and paired devices with revocation.

It follows the layout of Tauri's `create-tauri-app` React + TypeScript template: the frontend is
a Vite project in `gui/` (`index.html`, `src/`), and the Rust side is in `gui/src-tauri/`. Building
it needs Node and [pnpm](https://pnpm.io):

```sh
cd gui
pnpm install
pnpm tauri dev
```

`pnpm tauri dev` starts Vite and the app together and reloads the window as the frontend changes.
To pass options to the app, put them after two `--`: `pnpm tauri dev -- -- --data-dir <dir>`. It
accepts `--data-dir <dir>` and `--port <port>` like the CLI, and uses the same data directory by
default, so don't run both at once. `pnpm tauri build` makes an app bundle.

In `gui/src/`, `store.ts` is a single [zustand](https://zustand.docs.pmnd.rs) store with
everything the components share: the server's status (polled once a second), the commands in
flight, the toast and the pairing requests on screen. `backend/` has the typed Tauri commands and
the shapes of what they return, `components/` the React components by area of the window, and
`styles/` the CSS. `pnpm lint`, `pnpm format` and `pnpm build` (which typechecks) check the
frontend; `pnpm install` also sets up a pre-commit hook that runs ESLint and Prettier on staged
files.

`pnpm test` runs the frontend's tests with [Vitest](https://vitest.dev): the helpers and the store
directly, and the components rendered into jsdom against a fake backend made with Tauri's
`mockIPC` (`src/test/`). The types in `src/backend/bindings/` are generated by
[ts-rs](https://github.com/Aleph-Alpha/ts-rs) from the Rust structs the commands return, which
live in their own small crate, `gui/types/`: after changing them, run `cargo test` and commit what
it writes. CI runs all of this, and fails if the committed bindings are out of date.

The Tauri crate is a workspace member but not a default member, so `cargo build` and `cargo test`
at the root don't build it (on Linux it needs the WebKitGTK development packages). They do build
`gui/types/`, which needs nothing more than serde.

### Releasing the macOS app

Add the [GitHub Actions repository secrets](https://github.com/milesegan/minimoon-media-server/settings/secrets/actions)
used by Android Sync: `APPLE_CERTIFICATE` (the base64-encoded Developer ID Application `.p12`),
`APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (an
Apple app-specific password), and `APPLE_TEAM_ID`.

Keep the versions in `Cargo.toml`, `gui/src-tauri/Cargo.toml`, `gui/types/Cargo.toml`, and
`gui/package.json` in sync, and update `Cargo.lock` with `cargo update --workspace`. Tauri reads
the app version from `gui/src-tauri/Cargo.toml`. Commit the version changes, then push a matching
tag from that commit (for example, `git tag v0.5.0` and `git push origin main v0.5.0`).

The [macOS release workflow](.github/workflows/release.yml) checks the versions, runs the Rust and
frontend tests, and signs the universal app and DMG. It submits the DMG to Apple and verifies the
attached notarization ticket before uploading to a draft GitHub release. The release goes live
once the installer is attached.

## HTTP API

All routes are under `/v1`; see the spec for the full contract.

| Route | |
|---|---|
| `GET /v1/server` | Server id, name, auth mode, protocol version and features, shared folders, and the index's current ETags |
| `GET /v1/index[?view=files]` | The full index of every shared folder, or its file list |
| `GET /v1/items/{id}/content` | File bytes, with ranges, `If-Range` and `If-None-Match` |
| `GET /v1/items/{id}/art[?maxSize=N]` | The first embedded picture, optionally resized to JPEG |
| `GET /v1/items/{id}/lyrics` | Embedded lyrics as plain text |
| `GET /v1/events` | Server-Sent Events: `index-changed`, `folder-availability`, `shared-folders-changed` |
| `POST /v1/pair`, `POST /v1/pair/{id}/confirm` | Pairing (when pairing is on) |
| `GET /v1/items/{id}/content-url`, `GET /v1/c/{id}?…` | Signed media URLs for players that can't send headers |

## How it works

- **Settings** (`settings.json`): the server id, shared folders with their UUIDs, display names
  and volume mount points, bumped `rev` values, the last FSEvents event id, and pairing state.
  None of it can be rebuilt from the disks, so the file is never replaced silently.
- **Index** (`index.sqlite`): each shared folder's last published snapshot, with every file's
  metadata, reader version and read status. Deleting it loses nothing that the next scan
  doesn't read again; ids and `rev` values come back unchanged.
- **Scanning:** a full scan at startup and every 30 minutes, and a debounced rescan after file
  events. Before and after each walk the folder's volume is checked, so an unplugged drive
  never looks like deleted files. Anything a walk can't read is treated as not there, and a
  completed scan is published in one step, once the metadata of every new or changed file
  has been read.
- **`rev`:** a file written in place with its size and mtime unchanged (some taggers put the
  old mtime back) gets a new `rev` when the watcher reported the write and the file's ctime
  moved. On macOS the server runs its own FSEvents stream and resumes from the stored event id,
  so writes made while it was stopped are replayed. On Linux and Windows it uses the `notify`
  crate.
- **Metadata:** audio through `src/reader/audio.rs`, a read-only copy of the apps'
  `minimoon_tags` reading code over `lofty`; video through `src/reader/video/`, built on
  `matroska-demuxer`, `mp4-atom`, `scuffle-h265`, `h264-reader` and `scuffle-av1`. Reads run on
  worker threads with a time limit. Temporary failures are retried with backoff, and files read
  by an older reader version are re-read in the background.
- **Sleep:** while content is streaming, and for ten minutes after, the server holds an
  idle-sleep assertion on macOS and Windows.

## Library use

The desktop app embeds the server through `MediaServer`:

```rust
use minimoon_media_server::{LibraryOptions, MediaServer, ServerOptions};

let server = MediaServer::start(ServerOptions::new(LibraryOptions::new(data_dir))).await?;
let folder = server.library().add_shared_folder(path, None)?;
```

`Library` covers shared folders (add, rename, remove),
"Reindex everything" and per-folder status with error counts. `MediaServer` adds pausing,
pairing mode, paired devices and revocation, the display name and "Keep this computer awake".
